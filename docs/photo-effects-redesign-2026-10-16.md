## 实现与兼容

- 画面处理通过 `PhotoSurfacePlugin` 注入照片正反面共享材质，覆盖漫反射与自发光采样。切换效果只更新 uniform；保持原照片、纹理池和材质身份，不额外创建渲染目标。照片网格为 24 × 24 分段，支持真实曲面形变。
- 八种编排共用当前位置、拖拽、滚轮、键盘与逐张导航机制；切换编排仍平滑过渡，单张与手机屏幕保持聚焦构图。
- 自动漫游停留时间按活动时间推进，与用于平滑位姿的帧步长分别计算；低帧率或空闲限帧不会把每张照片的停留时间成倍拉长。
- 减少动态效果时停止照片表面动画、形变和指针扰动，保留静态画面处理与手动导航。动画速度 0 时停止表面时间推进；后台和灯箱暂停复用引擎现有生命周期。
- 旧的未自定义预设在渲染时补齐照片处理，不重写已存历史。第一次修改或切换访客布局时保留正在显示的处理，避免 `customized` 标记让效果消失。旧自定义配置保持原有意图，显式选择原片优先。
- 前后端同步校验 `effects.photo.style / intensity / speed` 与 `layout.params.arrangement`，复用配置版本 1 和现有发布通道。
- 平面展览、灯箱和下载继续展示原片；照片文件本身没有被修改。

## 验证与复现

- `npm run test:viewer:unit`：154 项通过，覆盖预设独立性、参数边界、旧配置编辑、访客布局保留画面处理、资源恢复、编排与低帧率漫游节奏。
- `npm run build`：管理端与访客端类型检查、生产构建通过。
- `photo-effects.spec.ts`：固定照片、背景和布局，验证全部 16 种处理与原片以及彼此之间的像素差异；0% 精确恢复原片；运动、0 速度和减少动态效果；手机上八种编排可导航。
- `effects.spec.ts`、`photo-surfaces.spec.ts`：整套预设切换无着色器错误，正反面仍保持照片方向、颜色与完整内容。
- 管理端 `viewer-config.spec.ts` 的专项验收：选择预设、调整画面处理/强度/速度/编排、实时 iframe、保存重载与 1440 / 1024 / 390 像素布局。
- Java `ViewerConfigValidatorTest`：5 项通过，含前后端共享参数校验样例。
- `photo-resources.spec.ts`、`quality.spec.ts`、`stage-runtime.spec.ts`：200 / 500 张照片身份与纹理驻留预算、失败纹理重试、模式替换、自动画质预算、低画质回退与自动漫游。

启动访客端开发服务后运行 `node scripts/render-photo-effect-previews.mjs` 可用项目内同一张海岸照片重建 16 张 WebP 缩略图（约 150 KiB 总量）及 `.cache/photo-effects/comparison.webp` 对照图。照片、布局、背景与光照固定，仅切换照片处理。生成器检查截图颜色丰富度，避免将未渲染照片的纯色画布写入预览。

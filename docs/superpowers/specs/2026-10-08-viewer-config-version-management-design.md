# 展厅配置版本命名与历史管理设计

日期：2026-10-08。代码基线：`6ffef6997f4413d897c003a4e9cec4e8450398fe`。

状态：待用户审阅。本文获批后再编写实施计划并开始产品代码实现。

## 1. 目标与范围

发布配置时允许输入可选名称和备注，以便用户区分相同配置的多次发布；为每个版本分配稳定、单调递增的编号；允许编辑历史版本名称与备注、恢复历史快照到草稿、删除非当前历史版本。用户无需填写名称即可发布。

这里的版本是“展厅展示配置版本”，包含配置 JSON、预设名和 schema 版本，不包含相册照片或其他相册资料。产品界面及接口应清楚表达这一范围。

本次覆盖数据库迁移、领域/仓储/服务/API、管理端发布入口和版本历史列表、共享契约、自动化验证。保留现有发布授权、公开访问、草稿编辑及相册发布语义。版本元数据仅在管理端显示，不加入公开访客响应。

## 2. 现状与问题

- 版本数据目前只有配置快照、预设、schema、创建时间和创建人，没有版本编号、名称、备注。
- 管理端 `GalleryConfigPanel.vue` 已读取 `title`、`versionNumber`，但控制器响应没有这些字段；当前版本展示还会覆盖版本自身标题。
- 配置面板发布和工作区发布中心是不同流程；工作区发布中心可能在“发布相册”时先同步配置，必须避免在没有新配置快照时询问或创建空版本。
- 版本恢复的主要 UI 路径会将历史配置保存为草稿；后端 `/rollback` 却总是创建并发布新版本，和请求体的 `publish:false` 及 UI 语义冲突。
- 版本表的外键在删除目标版本时会将发布指针置空，因此物理删除前必须保护当前版本。
- 历史列表当前只显示前 10 条，列表标题被用于触发恢复，缺少明确的编辑和删除操作。

## 3. 方案与产品行为

选择：系统自动版本号 + 可选名称 + 可选备注。编号是可靠身份，名称方便扫读，备注说明变更原因。名称最多 60 个字符，备注最多 500 个字符；可重复，按纯文本处理。去除首尾空白，空值存为 `null`。版本编号相册内唯一、严格递增、删除后不复用。

版本列表显示名称（空名称显示“配置版本”）、编号、发布时间、备注和独立的“当前使用”状态。当前使用状态不替换版本名称。当前版本突出显示；历史列表每页 20 条并可加载更多，当前版本摘要不受分页影响。

发布确认面板包含选填版本名、选填备注及自动编号说明。配置页和发布中心共用相同字段、验证与提示文案。发布错误保留用户输入；重复提交禁用；成功后更新当前版本并刷新列表。仅同步相册状态且未发布配置快照的流程不创建版本。

每条历史版本有明确的“编辑名称和备注”“恢复到草稿”操作；非当前版本另有“删除”。点击行本身不执行破坏性或写入操作。编辑元数据不修改配置快照或发布时间。

恢复操作先提示可能覆盖未保存修改，之后将快照校验并保存为草稿、刷新编辑器和预览。恢复不修改公开版本、不创建历史版本；用户之后发布草稿时创建新编号，原历史版本保留不变。

删除采用逻辑删除。确认弹窗明确版本名/编号、不能恢复及不影响照片和当前配置。删除后版本不再出现在列表或可恢复/编辑操作中，编号仍被占用。当前使用版本禁止删除，即使相册已撤回发布。删除历史版本不得更改草稿或发布指针。

## 4. 数据模型与迁移

为 `gallery_viewer_config_version` 增加：

| 字段 | 规则 |
|---|---|
| `version_number BIGINT` | 非空，正数，相册内唯一 |
| `title VARCHAR(60)` | 可空 |
| `note VARCHAR(500)` | 可空 |
| `metadata_updated_at DATETIME(6)` | 元数据修改时间，可空 |
| `metadata_updated_by_user_id BINARY(16)` | 修改人，可空，删除用户时置空 |
| `deleted_at DATETIME(6)` | 逻辑删除时间，可空 |
| `deleted_by_user_id BINARY(16)` | 删除人，可空，删除用户时置空 |

增加相册级版本计数器，以事务安全分配版本号；增加 `(tenant_id, gallery_id, version_number)` 唯一索引。不得用记录数或当前最大值加一作为无锁并发分配方案。

新迁移为所有既有记录按 `gallery_id, created_at ASC, id ASC` 赋予 v1 起的连续编号，当前发布 ID 与配置内容保持不变；相册计数器初始化为每个相册已分配的最大编号。历史名称、备注为空。旧迁移文件不回写。

## 5. API 与权限

所有端点位于 `/api/galleries/{galleryId}/viewer-config`：

| 方法与路径 | 行为 |
|---|---|
| `POST /publish` | 接受兼容可选的 `schemaVersion`、`title`、`note`，创建并发布快照 |
| `GET /versions` | 分页返回版本摘要、编号、标题、备注、创建时间、当前状态 |
| `GET /versions/{versionId}` | 获取快照配置详情 |
| `PATCH /versions/{versionId}` | 只修改标题和备注 |
| `POST /versions/{versionId}/restore` | 验证历史快照并保存成草稿，不发布 |
| `DELETE /versions/{versionId}` | 逻辑删除非当前版本 |

继续提供现有 `/rollback` 以兼容调用者，但管理端恢复操作迁移到明确的 `/restore`。任何旧调用的语义不得在此变更中悄然改变。

沿用当前租户隔离及权限：读取要求 viewer 权限，发布、元数据编辑、恢复、删除要求 editor 权限。跨租户或跨相册 ID 按不存在处理。被删除版本按不存在处理；重复删除成功。输入长度和空白规则由服务端强制，前端做即时校验。当前版本删除由事务内服务端检查，不能只依赖隐藏按钮。

列表响应可继续保留 `configJson` 以便现有调用方平滑迁移；迁移管理端依赖到详情端点后，可以在同一变更中将列表收敛为摘要，但须先完成所有读者的迁移并更新契约。

## 6. 事务、一致性与错误

- 发布：锁定相册计数器、分配新编号、插入不可变配置快照、更新当前发布指针及草稿发布元数据，在同一事务提交。
- 元数据编辑：按租户/相册/版本确认未删除，再更新名称、备注及元数据审计字段，不触碰配置快照。
- 恢复：确认版本存在且未删除，校验其配置，并保存草稿；不调用发布指针更新。
- 删除：锁定相册并在同一事务中校验发布指针，拒绝当前版本，设置删除标记。
- 并发发布产生不同的顺序编号；并发删除/恢复不能让已删除版本被写入草稿。
- 前端发布流程可能先提交配置快照、再发布相册。若后一步失败，必须准确提示配置快照已成为当前版本，重试相册发布时不得再次制造相同快照。
- API 错误码至少区分版本不存在、当前版本不可删除、输入无效和发布失败；前端保留输入或列表原状，并提供可理解提示。

范围内不做版本差异比较、回收站/撤销删除、分支、公开展示版本名称、照片/整相册快照或额外审计平台。

## 8. 验收标准

- 未填写名称与备注可正常发布，并获得相册内稳定的新版本号。
- 重名名称、中文和备注换行可正确保存/显示；超长输入由前后端拒绝。
- 旧版本回填后编号确定、唯一，现行公开配置及发布指针不改变。
- 当前版本显示真实标题和独立状态；元数据编辑不生成新版本。
- 删除中间和最新历史版本后编号不重排、不复用；当前版本无法经 API 删除。
- 恢复只更新草稿，公开端保持原配置；后续发布产生新快照且原历史版本可用。
- 未授权、跨租户、跨相册、已删除 ID 的访问按规则拒绝；开发内存仓库行为与正式仓库一致。
- 并发发布不重复编号；并发删除与恢复不会使用已删除快照。
- 配置页和发布中心行为一致，后续相册发布失败的重试不会重复发布配置。
- 历史分页、空状态、长文本、错误和窄屏布局在真实浏览器可用。

# 照片配置特效与性能升级设计

日期：2026-10-05

状态：设计草案，待用户审阅；升级范围已在对话中确认

范围：配置工作台、共享配置契约、3D Viewer、配置校验与验收

定位：开源项目，全部场景和特效开放，不引入收费、订阅或权益判断

## 1. 已确认的目标

上传、配置、发布和分享链路已经存在。本次升级解决的是配置效果不足：用户应能制作明显不同的展示风格，参数调节应真实改变画面，特效开启后仍有可控的资源开销。

用户已确认采用“丰富场景 + 完善参数 + 性能自适应”的范围。以下参数边界和验收数字是本设计提出的工程标准，尚非已测得的性能结果。

成功条件：

- 一键场景在空间构图、粒子、色彩与相机行为上可辨识；不只是换名称或雾色。
- 每个开放控件都有渲染消费者，且保存、刷新、预览、发布、回滚后的配置一致。
- 性能策略根据运行负载调整实际渲染，不修改保存的创作意图。
- 已有相册、历史配置和分享链接继续可用。

## 3. 范围与取舍

采用参数化现有布局、复用现有插件、共享预设定义的方案。新增独立场景背景和统一后处理能力，不重写整个引擎。

本期交付：六种布局可调、八种场景预设、六种已有粒子的参数化、独立调色和暗角、照片动画参数、运行时画质预算，以及配置链路和真实浏览器验收。

本期不新增体积光、实时反射、景深、多套渲染引擎、音乐上传或播放系统。已有音频字段兼容保留，管理端不继续展示未实现的音乐效果开关。品牌站收费语义和开源许可证另行处理，不混入本次照片特效改造。

2D 照片墙和灯箱继续保持清晰、易访问的照片浏览。3D 氛围调色不应用于灯箱图片或下载资源；场景背景不覆盖管理端和品牌站的全局样式。

## 4. 配置契约与数据流

### 4.1 共享配置

在 `packages/gallery-contracts` 增加照片展示配置类型、默认值、规范化函数及预设注册表。管理端和 Viewer 消费同一份定义；不再各自维护同名预设。现有 `ViewerConfig` 成为共享类型的导入或别名。

继续使用现有 `configJson` 和 schemaVersion=1，本次字段均为可选扩展；不改变已有字段含义，不批量改写数据库历史快照。后续破坏性变更才提升 schemaVersion。

规范化区分两条路径：

- 管理端编辑、保存及预览消息：验证字段类型、枚举、有限数值、颜色和边界；非法输入定位到字段，阻止保存或应用。
- 访客读取历史配置：缺失字段补默认值，已知旧字段转换；非法字段使用安全默认并记录可诊断原因，不让相册整页崩溃。

只递归处理普通对象自有属性，忽略危险键 `__proto__`、`constructor`、`prototype`；配置 JSON 限制为 UTF-8 64 KiB，嵌套深度最多 8。拒绝非对象根节点、未知 schemaVersion 和错误 JSON。后端在保存、发布、回滚前验证 JSON 结构、已知参数类型与范围；共享合法/非法夹具验证 TypeScript 与 Java 的一致性。

保存时保留可安全解析的未知扩展字段，避免编辑旧配置时破坏已有扩展；它们不参与运行时渲染。所有修改基于规范化后的完整配置，禁止从控件重新拼出会遗漏字段的配置。

### 4.2 参数设计

以下默认值用于新字段；原字段缺省值按旧配置兼容规则处理。

| 分组 | 字段及边界 | 默认与语义 |
| --- | --- | --- |
| 布局 | `layout.params.scale` 0.5–2；`spacing` 0.5–3；`radius` 100–1500；`columns` 整数 1–12；`height` 100–1500；`turns` 0.5–6 | scale=1、spacing=1；其余未指定时沿用生成器自动值；columns 仅网格，height/turns 仅螺旋布局 |
| 转场 | `layout.transition.duration` 0.2–3 秒；`style` 为 smooth / burst / none | 1.2 秒、burst，保留现有空间弧线转场；none 立即应用 |
| 粒子 | `density` 0–2；`speed` 0–2；`size` 0.5–2；`color` 为可选六位十六进制颜色 | 1、1、1、未指定；速度为零冻结；未指定颜色保留每种粒子的原始配色 |
| 背景 | `background.mode` 为 solid / gradient；`color`、`secondaryColor` 为六位十六进制颜色；`angle` 0–360 度 | solid、#0f172a、#163124、135；只作用于 Viewer 场景背景 |
| 调色 | `effects.postGrade.enabled`；`saturation` 0–2；`brightness` 0.5–1.5；`contrast` 0.5–1.5 | 新场景默认关闭；数值均为 1；亮度作用于 3D 场景后处理，不修改原图 |
| 暗角 | `effects.vignette.enabled`；`strength` 0–1 | 默认关闭、0.25；可单独开启，与辉光无关 |
| 照片动画 | `effects.photoFloat` 沿用；新增 `floatAmplitude` 0–2、`floatSpeed` 0–2；`photoEntrance` 为 fade / rise / none；`entranceDuration` 0.2–2 秒 | 1、1、fade、0.5 秒；关闭悬浮时平滑回到布局基准姿态 |
| 相机 | 沿用 autoRotate / introFlight；新增 `rotateSpeed` 0–2、`introDuration` 0.5–4 秒 | 0.5、2 秒；用户拖拽立即中断入场运镜 |
| 画质 | `quality` 沿用 auto / low / mid / high | auto；指定画质设置期望上限，自动保护仍可降低有效画质 |

照片尺寸由 scale 调整，宽高比始终保留；spacing 应用于布局中心的坐标缩放。生成器特有参数先用于生成基础布局，再应用 spacing。少量照片特殊构图也应用 scale/spacing；radius 等布局特有参数在不适用时隐藏，并保留已保存值。

密度作用于质量档基础数量：先按类型计算 `round(baseCount * density)`，再按总预算比例缩减，整数余量按固定类型顺序分配。density=0 不生成粒子；不能使用 `density || 1`。颜色/速度变更只更新 uniform 或动画参数；密度和类型变更才调整实例数量。多种粒子共用总预算。

### 4.3 意图与实际画质分离

配置流为：历史配置读取 → 规范化 → 编辑草稿 → 校验保存 → 现有发布快照 → 访客读取 → 推导设备有效配置 → 渲染。

`requestedConfig` 保存完整创作意图；`effectiveConfig` 由质量档、性能采样、照片数量和减少动态效果偏好推导。预览使用同一套推导逻辑，并向管理端报告有效画质和降低开销的原因；性能结果不会触发草稿变更或自动保存。

普通访客只看到“已优化显示效果”或可操作的画质切换。FPS、纹理数、预算等调试指标继续留在开发诊断入口，不常驻访客界面。

## 5. 八种场景预设

保留所有现有 presetName，新增两个名称。预设写入完整、确定的受支持效果字段，消除前一场景的残留；下载权限、未知扩展字段和用户画质偏好不随场景切换。

| presetName | 名称 | 可见差异 |
| --- | --- | --- |
| minimal | 极简展馆 | 网格展墙、纯色中性背景、无粒子、无调色与辉光、静止照片 |
| forest-dream | 森林萤火 | 双螺旋、深绿渐变、萤火与少量樱花、柔雾、缓慢悬浮 |
| starry-night | 星空漫游 | 球面布局、深蓝背景、星尘与流星、克制辉光、慢速环绕 |
| ocean-breeze | 海风蓝调 | 旋臂布局、海蓝渐变、轻雾、低饱和调色、无高密度粒子 |
| sunset-glow | 暖色落日 | 曲面展墙、橙褐渐变、暖光、少量樱花、轻暗角 |
| romantic | 浪漫光影 | 环幕布局、紫粉渐变、心形与萤火、柔和辉光、照片淡入 |
| snowfall | 静谧雪境 | 网格展墙、蓝灰渐变、缓落雪粒、中性照片颜色、弱辉光 |
| film | 胶片记忆 | 环幕布局、暖黑纯色、暖光、低饱和高对比和暗角、无粒子 |

效果应突出照片可读性；胶片场景不添加高开销实时噪声，粒子不得遮挡主要交互。每个预设用同一组照片、固定相机和固定质量截图对照，人工确认上述差异。

历史配置中只有 presetName 而没有参数时，使用共享兼容模块中冻结的旧预设定义，再补充中性新字段，不自动升级成上述新场景；已有显式参数优先于旧预设。用户主动点击场景卡片时才写入新的完整预设。切换光照时段只更新光照，不隐式覆盖用户的辉光、雾或调色设置。

## 6. 渲染职责与生命周期

### 6.1 后处理和背景

统一由一个后处理组件管理 EffectComposer、RenderPass、可选 BloomPass、可选调色/暗角 ShaderPass 和一次 OutputPass。无后处理时直接 renderer.render；仅调色开启时也能正确运行。原 Bloom 插件职责收敛到辉光参数，避免多个插件竞争 composer。

背景插件使用场景内背景或可释放的渐变纹理，不向 document 根节点写品牌颜色。后处理 resize 和 DPR 变化由引擎单点通知，避免插件回调和事件重复执行。销毁时显式释放每个 pass、render target 和渐变纹理；不能只销毁 composer 就假定所有 pass 已释放。

### 6.2 热更新与动画

应用配置时先规范化完整候选配置，再按插件是否需要存在进行增删，最后更新参数。判断使用合并后的完整配置，不能把部分更新缺失的 enabled 当作关闭。高频更新串行处理，尚未应用的消息合并为最新候选；配置序号防止异步旧结果覆盖新结果。

clickRipple 的开关也纳入装卸处理。仅变更颜色、强度、速度时不重装插件。帧循环、光照、淡入、布局和相机统一使用引擎活动时间；使用 delta 累计并限制单帧最大增量。页面隐藏时暂停更新和渲染，返回时重置帧采样，活动时间不推进。

入场动画使用时间调度表代替每张照片 setTimeout；总交错延迟不超过 1 秒。动画结束清理状态，删除照片取消其动画。插件重装、销毁、WebGL 丢失时清理监听、加载任务和转场计数；不得残留无法结束的 transition:start。

`prefers-reduced-motion` 下关闭入场运镜、悬浮、自动旋转和持续粒子动画，布局瞬时切换；静态色彩和布局仍保留。

## 7. 照片与性能策略

### 7.1 增量照片与纹理

分页追加保留原照片对象及其 Mesh，以当前载入对象身份为键维护映射；不增加公开接口字段。完整刷新或换馆才重置映射。布局可重新计算已有位置，但不重建未删除照片的几何、材质和纹理。

加载队列限制并发，视口附近照片优先。无纹理时显示中性占位，加载成功后入场；纹理失败回退 thumbnail，再失败显示可读占位并提供重试。优先使用 textureUrl，按档位限制上传 GPU 的最大纹理边长；较低质量下可采用 thumbnail。图片下载成功不等于 GPU 纹理就绪，指标区分两者。

只让预算内的照片持有完整纹理；其余保留照片数据和低成本占位，根据视锥及相机距离按需换入。回收远离视口的纹理，使用最近使用时间避免频繁换入换出。软预算估算 RGBA8 带 mipmaps 为宽×高×4×4/3，不将估算值称为实测显存。

| 有效档位 | 最大 DPR | 纹理边长 | 照片纹理软预算 | 纹理并发 | 最大驻留照片纹理 | 总粒子实例预算 | 后处理分辨率比例 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| low | 1 | 512 | 32 MiB | 2 | 32 | 200 | 0.5 |
| mid | 1.5 | 1024 | 64 MiB | 3 | 64 | 700 | 0.75 |
| high | 2 | 2048 | 128 MiB | 4 | 96 | 1600 | 1 |

驻留上限和软预算同时满足，以先达到者为准；后处理目标按 canvas 实际尺寸×有效 DPR×比例设置。资源预算中的粒子实例为总数，樱花/心形等高成本实例优先缩减。几何、材质在完整销毁后归零；粒子和后处理各自单独释放。

### 7.2 性能自适应

保留活动 60 FPS、空闲 20 FPS 的调度基础。空闲、页面隐藏、失去 WebGL、加载或布局转场期间不计入降级判定。持续粒子运动和自动旋转允许空闲节能，但主动空闲限帧不得误触发性能降级。

启动档位保守推导：手机和明显低资源设备为 low，其余 auto 从 mid 开始；显式 high 不高于上述资源硬上限。设备信息缺失不假定高性能。

主动交互且无加载/转场时，每秒采样一个窗口；连续 3 个窗口 FPS < 30 降一级，连续 8 个窗口 FPS >= 55 可升一级。每次调整冷却 10 秒，每次调整后重新统计窗口；不会升到用户指定上限之外。优先同步降低 DPR、后处理分辨率、粒子及纹理预算，仍在 low 持续低于 20 FPS 5 秒则回退 2D 并允许用户重新尝试 3D。

采样同时记录帧时间 p50/p95、draw calls、纹理和几何数、预算估算及降级原因。FPS 的样本只计真正渲染帧；帧时间区分调度间隔和实际 update+render 开销，避免将空闲限帧理解成 GPU 瓶颈。

## 8. 配置工作台与预览

保留现有“基础 / 氛围 / 高级 / 版本”入口和真实 iframe 预览。

- 基础：布局、适用的布局参数、照片尺寸、场景卡片；提供恢复当前场景默认参数的动作。
- 氛围：背景、粒子类型及强度、光照、独立辉光、调色、暗角。
- 高级：转场、入场、悬浮、相机速度和画质上限；技术参数默认折叠。
- 版本：沿用草稿发布和回滚，显示历史场景名称；无法识别的旧名称按自定义处理。

控件提供数值和简短结果描述，滑块为键盘可操作，颜色输入有格式提示。修改场景后手动调参标为“已自定义”，仍保留来源场景信息用于恢复默认；不因某个小改动将整个预设强制重载。

沿用 120ms 预览消息节流；使用 iframe 已确认的 origin 发送，并校验接收来源为预期父窗口/iframe。消息携带序号，Viewer 应用后返回序号、有效画质和必要的限制原因；过期返回不覆盖工作台状态。内部预览令牌按原机制工作，不泄露到日志或公开链接。

## 9. 兼容与失败恢复

- schemaVersion=1 历史数据缺失新字段时保持旧布局、颜色及粒子行为。旧 bloom 开启时隐含的调色/暗角转换为显式启用参数，旧 bloom 关闭时转换为关闭；转换完成后它们作为独立效果编辑。
- 旧布局参数 rx/ry/rz、cellW/cellH、cols、baseRadius/maxRadius 若存在，读取时保留并透传给对应生成器；cols 映射到 columns。新管理端只编辑规范字段，规范字段与旧参数冲突时使用规范字段；未冲突的轴向半径及单元尺寸保留，不能将椭球参数压成单一半径。
- 新默认只适用于新建配置或主动切换预设；读取历史数据不得自动添加新的相机运动。
- 后端先兼容新字段，随后发布可读取新字段的 Viewer，最后启用管理端新控件；部署说明提醒旧 Viewer 会忽略新能力。
- 配置应用失败时保留最后一次有效状态，显示可重试错误，不保存半应用配置；纹理失败局限于该照片；后处理初始化失败切回基础 3D，WebGL 不可用切回 2D。
- 部分插件初始化失败先回收已申请资源；迟到的异步结果在引擎销毁后释放，不再加入场景。

## 10. 验收标准与证据

### 10.1 自动化正确性

共享契约使用边界和历史夹具测试：空配置、旧预设、缺少字段、density=0、未知扩展、非法 JSON、非法颜色、越界数值、危险键。覆盖序列化往返，不仅比较函数内部返回值。

渲染行为测试覆盖：密度改变实际实例数；速度为零冻结；radius/spacing/columns 影响位置；调色开启但辉光关闭仍有效；快速开关每个插件后实例和监听不重复；部分更新不误关插件；统一计时下淡入/光照在预期时间结束。

端到端覆盖：保存→刷新→草稿预览→发布→访客读取→回滚；预览消息来源校验；最新序号胜出；WebGL 故障回退；图片失败与重试；减少动态效果偏好。不能只检查 canvas 出现或配置成功下发。

### 10.2 视觉检查

固定 12 张本地横竖照片，统一随机种子、时间、相机、视口和画质，保存八种场景截图；检查照片可读、构图无重叠导致的不可操作、粒子形状可辨、背景差异、调色独立和控件可见变化。桌面 1440×900，移动 390×844。

### 10.3 性能门槛

建立同机前后对照：记录 CPU、GPU/渲染器、内存、浏览器版本、WebGL 是否硬件加速、视口、DPR、质量、照片尺寸、加载耗时和首次可见照片时间。固定本地照片资源，避免网络波动混入渲染对比。先热身 10 秒，再采集 30 秒主动交互窗口，每个用例运行 3 次，报告中位数和 p95。

| 用例 | 必须满足 |
| --- | --- |
| 桌面 50 张、mid、starry-night、主动环绕 | 三次运行中位 FPS >= 50，帧间隔 p95 <= 33ms |
| 真实移动设备 50 张、low、forest-dream | 中位 FPS >= 30，帧间隔 p95 <= 50ms；模拟手机视口不能替代真实设备 |
| 200/500 张渐进加载 | 不超过有效质量纹理预算、并发和驻留上限；追加时不重建已有纹理，不出现单次 >200ms 的同步脚本长任务 |
| 连续 20 次场景切换和 10 次 2D/3D 切换 | 无未处理异常；返回同一场景稳定后纹理/几何数无持续增长，误差不超过初始稳定值的 10% 或 2 个资源（取较大值） |
| 同一画质和场景的前后对照 | 稳定状态纹理估算不增加，CPU update+render p95 开销不劣化超过 10% |
| 降级、空闲和隐藏页面 | 人为空闲 20 FPS 不触发降级；负载下降按迟滞恢复；隐藏期间不渲染；返回后动画不跳跃 |

GPU 无法满足首两项时保留失败结果并调整实现，不删减用例或降低门槛后声称通过。无真实移动设备时标记该项“未验证”，不得以桌面模拟验收替代。

文档记录测试命令、机器信息、截图、指标和限制。无需为纯文案或布局样式写镜像测试；重点测试跨模块配置行为、渲染资源和恢复路径。

## 11. 实施边界与顺序

后续实施计划按以下可验证阶段展开：

1. 共享配置与兼容夹具，后端输入验证。
2. 修复参数贯通、计时及热更新，已有能力先真实生效。
3. 独立后处理和场景背景，八个共享预设。
4. 增量照片加载、纹理/粒子预算和画质自适应。
5. 管理端控件与预览反馈贯通。
6. 配置生命周期、视觉、性能和故障回归。

主要修改区域为 `packages/gallery-contracts`、管理端配置页、Viewer 的 core/plugins/lib/App.vue，以及后端配置 facade/domain 校验和相关测试。上传任务、成员管理、分享鉴权和品牌站模板不扩展功能。

本文件是设计规格；不把已有 README 中的“V1 Ready”或代码中的“生产级”注释当作本次能力的验收证据。

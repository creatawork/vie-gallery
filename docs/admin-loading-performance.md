# 管理端加载优化验收

日期：2026-10-08。

## 根因与改动

- 展厅配置的请求虽然并发发出，但配置处理与面板展示仍等待预览凭证。现将凭证签发独立执行：预览慢或失败时仍可编辑，失败后支持重新连接；离开页面及后续重试会忽略过期凭证响应。
- 工作区先取展厅信息再取照片，两个独立读取串行。现并行请求并在成功后一起提交结果，保留请求版本检查，避免失败或切换页面后的旧照片回写。
- 公共 API 客户端只为写入设置超时，读取可能长期等待。现读取也使用已有的 30 秒响应等待超时（不包含响应体后续读取），并保留调用方取消语义。
- 多个并发写入在首次使用时重复获取 CSRF 凭证。现共享进行中的请求，成功后使用原有缓存，失败后释放以允许重试；写入收到 403 时仍清除缓存。

## 对比证据

以 Chromium 加载实际 Vue 工作区 composable，比较修改前 HEAD 与当前源码；展厅和照片接口各模拟 300ms 延迟，分别独立运行 5 次：

| 工作区数据加载 | 样本（毫秒） | 中位数 |
| --- | --- | --- |
| 修改前 | 616、617、615、616、614 | 616ms |
| 修改后 | 307、306、306、306、313 | 306ms |

该受控场景缩短约 50%，反映移除串行等待的收益，不是生产环境页面加载速度承诺。

浏览器回归还确认：

- 挂起预览凭证时，修改前 2 秒内配置控件未出现；修改后同一测试中控件已可用，释放凭证后真实 viewer iframe 正常就绪。
- 3 个同时发起的写请求，首次 CSRF 请求数量从 3 次降为 1 次。
- 读取请求无响应时，推进浏览器时钟至 30 秒后返回可识别超时错误。
- 凭证失败可重试；配置预览凭证失败不会阻塞编辑。

## 验证方式与范围

- `npm run verify`：文档链接、两端类型检查与生产构建。
- `npm run test:viewer:unit`：95 项通过。
- 管理端 Playwright 全套：28 项通过（58.7 秒）。生产形态同域静态服务器，后端响应由测试夹具提供，真实 Chromium 与 viewer iframe；viewer 构建开启 `VITE_VIEWER_DIAGNOSTICS=true`。
- 新增回归在 `api-loading.spec.ts`、`creation-flow.spec.ts` 和 `viewer-config.spec.ts`。

本次定位与验证覆盖管理端公共请求层、工作区及展厅配置。没有生产接口瀑布或数据库计时，因此不声称已解决线上全部延迟。Viewer 的 Three.js 分包仍约 684KB（gzip 176KB），构建保留原有大小警告；本次未改变 3D 画质、模型资源或后端接口。

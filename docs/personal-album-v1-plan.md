## 1. 产品定义

VIE Gallery V1 是面向个人用户和个人创作者的照片相册产品：用户可以可靠保存照片，按相册记录和整理内容，创作 2D/3D 展示体验，通过受控链接分享，并在一个简单的工作台中管理相册和处理任务。

本期的最终结果不是“拥有一组 3D 特效”，而是：

> 用户能够在不阅读内部技术文档的情况下，创建一个相册，上传照片，等待处理完成，预览并发布，安全分享给访客，之后还能回来继续整理和更新。

### 1.1 目标用户

- 以个人使用为主的照片记录者；
- 摄影师、独立创作者和需要交付照片的个人工作室；
- 不要求企业组织、团队审批或多租户运营经验的普通用户。

### 1.2 产品主循环

```text
注册/登录
  → 创建相册
  → 上传照片
  → 后台处理与保存
  → 整理记录
  → 配置展示体验
  → 预览草稿
  → 发布
  → 创建分享链接
  → 访客浏览
  → 查看访问摘要并继续更新
```

### 1.3 产品原则

1. **照片优先**：3D 是增强体验，不是访问前提；任何不支持 WebGL 的设备至少可以使用 2D 浏览。
2. **事实优先**：状态、数量、更新时间和访问信息由服务端提供，不由前端猜测。
3. **可恢复**：刷新、网络中断、任务失败、Worker 重启和误操作都应有可理解的恢复路径。
4. **安全默认**：私密内容不因 URL、日志、Meta 或错误信息泄露；生产配置不能依赖开发默认值。
5. **结果导向**：文案和配置以“用户得到什么结果”为主，高级渲染参数折叠到高级设置。
6. **先完成再扩张**：本期完成个人相册上线闭环后，才评估后续领域。

## 2. 本期范围

本期只围绕个人相册的五个领域建设。现有 OWNER / EDITOR / VIEWER 模型作为权限实现基础保留，但不在本期继续扩展团队协作领域。

### 2.1 备份：保存原始照片并可恢复

本期备份不是“只把文件写进对象存储”，而是要让用户相信照片不会因一次请求或一次 Worker 故障丢失。

**必须完成**

- 原始照片可靠写入私有对象存储；
- 照片记录、对象记录、处理任务和配额之间有明确状态关系；
- 缩略图、高清图和 3D 纹理等衍生资源可重新生成；
- 上传失败、任务失败、取消、重试和 Worker 租约丢失可恢复；
- 删除行为、软删除、对象清理和配额释放语义明确且幂等；
- 提供孤儿对象/孤儿任务扫描与修复机制，至少有可执行的运维流程；
- 在管理端显示存储使用量和处理异常；
- 上线前验证数据库、Redis、MinIO 的备份与恢复演练。

**本期不承诺**

- 多地域灾备；
- 无限版本文件历史；
- 类似云盘的跨设备同步；
- 面向企业的合规归档和保留策略。

### 2.2 记录：让照片成为可整理的相册

**必须完成**

- 创建、编辑和删除个人相册；
- 相册名称、slug、封面、访问方式、发布状态和更新时间；
- 照片标题、顺序、封面选择和软删除；
- 照片状态清晰区分：处理中、已准备、失败；
- 相册总览支持真实的照片数、失败数、更新时间和状态；
- 空相册、无封面、长名称、上传失败和部分成功均有可用状态；
- 列表具备基础搜索、筛选、排序能力，避免相册数量增长后无法管理。

**可在本期后续小步加入**

- 备注、标签、章节和拍摄时间等更丰富的记录字段；
- EXIF 展示和按日期整理。

### 2.3 创作：配置可预览、可发布、可回退

**必须完成**

- 2D 网格和 3D 空间两种浏览模式；
- 场景化预设，普通用户无需理解 Bloom、DPR、Fog 等底层术语；
- 配置草稿与访客已发布版本分离；
- 保存草稿、发布、版本历史和回滚；
- 创作者/协作者可预览草稿，访客只看到已发布内容；
- 配置协议有 schema 版本、大小限制和数值范围校验；
- 3D 资源按设备能力和展示需要使用合适的资源等级。

**创作的完成标准**

用户修改配置后能明确知道：

- 草稿是否保存；
- 访客当前看到哪个版本；
- 哪些变更尚未发布；
- 发布错误后如何修复或回滚。

### 2.4 分享：受控访问而不是泄露链接

**必须完成**

- PUBLIC：无需凭证访问已发布内容；
- PRIVATE：仅持有有效分享 Token 的访客可访问；
- PASSWORD：通过密码解锁后访问，失败尝试受限流保护；
- 分享链接有效期、撤销、最近访问时间和状态展示；
- Token 不出现在公开 DTO、SEO canonical、日志和错误详情中；
- 公开端只返回已发布、READY 且未软删除的照片；
- 分享链接复制、二维码和移动端打开体验可用；
- 可配置访客是否允许下载；
- PUBLIC 相册具备社交预览 Meta；PRIVATE/PASSWORD 不泄露内容并正确 noindex。

**本期明确语义**

PRIVATE 当前定义为“仅持有有效分享链接的访客可访问”。登录用户直接访问 PRIVATE 相册属于上线后的后续能力，不作为本期隐含承诺。

### 2.5 管理：一个工作台完成日常操作

**必须完成**

- 注册、登录、退出和忘记密码/重置密码；
- 相册总览、创建、进入、返回和深链刷新；
- 上传队列与持久化任务中心；
- 每个文件的处理阶段、进度、错误、重试和取消；
- 相册内容、封面、顺序、配置、发布和分享入口；
- 存储用量、处理失败和待发布变更摘要；
- 统一错误码、requestId 和用户可理解的下一步；
- 手机宽度下无横向溢出，关键操作可完成。

**管理原则**

- 上传区域不再自行等待全部任务完成；任务中心是任务状态唯一事实来源；
- 所有可见按钮必须有真实行为或明确的禁用说明；
- 管理端显示“访客现在看到什么”，而不要求用户理解内部状态机。

## 5. 技术约束与实现顺序

### 5.1 状态边界

以下状态必须保持分离：

```text
访问权限：PUBLIC | PRIVATE | PASSWORD
相册生命周期：DRAFT | PUBLISHED | ARCHIVED
照片处理：PROCESSING | READY | FAILED
上传任务：QUEUED | PROCESSING | SUCCEEDED | FAILED | CANCELLED
配置状态：DRAFT | PUBLISHED（版本历史只追加）
```

访问权限不能代替发布状态；照片 READY 不能代替相册已发布；配置草稿不能直接改变访客公开版本。

### 5.2 数据与对象一致性

数据库记录是业务状态的事实来源，对象存储是内容载体。所有跨存储操作必须有：

- 可重试的操作边界；
- 幂等对象 key 或 attempt/version；
- 带前置状态条件的更新；
- 失败补偿和可观测日志；
- 定期对账，而不是用 `GREATEST(0, ...)` 等方式掩盖账目错误。

### 5.3 性能顺序

1. 先保证 2D 保底和 WebGL fallback；
2. 再实现 medium/texture LOD 和视野加载；
3. 再实现 FPS 阶梯降级；
4. 最后根据真实访问数据决定 CDN、预加载和更复杂的缓存策略。

不以新增特效替代性能闭环，不以本地单机 FPS 代替真实设备基准。

### 5.4 API 与契约

- 前后端共享 `packages/gallery-contracts`；
- 公开 API 与创作者 API 分离；
- 列表返回服务端事实摘要，避免前端 N+1 猜测；
- UUID、分页、上传文件名、配置 JSON 和错误响应统一校验；
- 用户可见 message 与内部诊断 detail 分离；
- 每个错误响应包含可追踪的 requestId，但不包含内部拓扑或对象 key。

## 6. 产品指标与上线后观察

### 6.1 首次成功漏斗

```text
注册
→ 创建相册
→ 上传至少 5 张照片
→ 处理完成
→ 首次发布
→ 生成分享链接
→ 分享链接被打开
→ 7 日内再次编辑
```

首批重点指标：

- 注册到创建相册转化率；
- 创建到上传转化率；
- 上传到首次发布转化率；
- 首次发布耗时中位数；
- 分享链接打开率；
- 7 日/30 日再次编辑率。

### 6.2 可靠性指标

- 上传成功率和部分成功率；
- 任务队列深度、最老任务等待时间；
- 处理成功、失败、重试、取消和租约恢复次数；
- 孤儿对象和配额对账差异；
- 存储读写失败率；
- 密码解锁限流次数；
- 公开访问 4xx/5xx 比例。

### 6.3 Viewer 指标

- 首屏时间和首张照片可见时间；
- 3D 初始化成功率；
- 2D fallback 触发率；
- 低 FPS 自动降级率；
- 移动端错误率；
- 纹理加载失败率；
- 100 张照片场景的 FPS 和峰值内存。

### 6.4 初始目标

这些是上线前需要采集和校准的目标，不是未经实测的承诺：

- 首次发布耗时中位数不超过 10 分钟；
- 关键处理任务成功率达到 99% 以上；
- WebGL 初始化失败时 2D 回退成功率为 100%；
- 中端设备首屏可见内容目标不超过 3 秒；
- 100 张照片场景无明显失控、白屏或浏览器崩溃；
- 分享访问成功、过期和撤销行为可在管理端解释。

## 7. 明确不纳入本期的后期领域

个人相册 V1 上线前不做以下方向，也不为它们提前引入复杂抽象：

- 多工作区切换；
- 邮箱邀请、团队组织和复杂成员协作；
- 评论、批注、审批和客户门户；
- 登录用户直接访问 PRIVATE 的完整方案；
- 企业级审计、合规保留和多地域灾备；
- 订阅套餐、在线支付和复杂商业化计费；
- AI 分类、智能选片和自动生成内容；
- 视频、音频和原生移动 App；
- 完整 SSR/SSG 重构；
- 多地域 CDN、复杂边缘计算和大规模流量优化；
- 社交关系、点赞、关注和公开社区。

这些方向只有在 V1 上线并获得真实用户反馈后，依据使用数据重新排序。

## 9. 本期完成定义

当以下条件全部满足时，个人相册 V1 才可以标记为“可上线”：

- 用户能完成个人相册的保存、记录、创作、分享和管理闭环；
- 原始照片、衍生资源、任务状态和配额有可恢复的一致性模型；
- 上传任务不会出现“后台成功、前端假失败”的主要状态分叉；
- 发布、配置发布、预览和回滚的语义对用户清晰；
- PUBLIC、PRIVATE、PASSWORD 的授权边界经过真实 HTTP 和浏览器验证；
- 3D 体验有 LOD、自动降级、资源释放和 2D 保底；
- 分享链接、社交预览、缓存和 Token 处理经过安全验收；
- CI、集成测试、迁移、备份恢复、监控和回滚手册齐备；
- 关键产品和可靠性指标能够被采集；
- 本期范围之外的后期领域仍保持明确隔离。

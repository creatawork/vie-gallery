# VIE Gallery V1 后一个月核心任务路线图

> **文档定位**：V1 Ready 验收通过后的首个月度执行规划  
> **规划日期**：2026-09-17  
> **基线状态**：V1 Ready 已于 2026-09-12 签字验收通过（见 [`v1-ready-signoff.md`](v1-ready-signoff.md)）

## 📋 总体目标

从"能用"提升到"好用"，完善核心功能体验，提升产品差异化竞争力，加固代码和安全基础。

### 核心指标

- **产品竞争力**：3D 展示效果业界领先，有明确的"wow moment"
- **功能完整性**：列表/网格视图功能对等，无明显短板
- **分享转化**：访客转创作者的路径清晰，分享数据可追踪
- **安全可信**：无明显安全漏洞，用户数据有保障
- **代码健康**：核心模块架构清晰，可持续迭代
- **细节专业**：交互流畅，文案友好，提示明确

### 🔐 WP-16：信息安全深度加固（2天）

**目标**：让用户信任产品的安全性

**具体任务**：

- [ ] **敏感信息审计**
  
  **1. 日志输出审计**
  - 扫描所有 `log.info`/`log.debug`/`log.error` 调用
  - 确保无密码、Token、重置令牌、签名 URL 泄露
  - 敏感字段使用脱敏工具类（如 `MaskUtil.maskEmail()`）
  - 文件：全局搜索日志调用
  
  **2. 前端 console 清理**
  - 生产环境禁用 `console.log`/`console.debug`
  - 使用构建时移除或条件编译
  - 文件：`vite.config.ts`（生产构建配置）
  
  **3. Error 信息脱敏**
  - 异常信息不暴露内部路径（如 `/app/src/...`）
  - 不暴露技术栈信息（如 "Spring Boot"、"MySQL" 等）
  - 统一错误处理器，返回用户友好信息
  - 文件：`GlobalExceptionHandler.java`

- [ ] **上传安全增强**
  
  **1. 图片文件内容校验**
  - 除了扩展名，还需校验文件头（magic bytes）
  - 防止伪装的可执行文件（如 `image.jpg.exe`）
  - 使用 Apache Tika 或类似库检测真实文件类型
  - 文件：`PhotoUploadService.java`
  
  **2. EXIF 恶意代码检测**
  - EXIF 数据可能包含恶意脚本
  - 使用 metadata-extractor 库解析
  - 清理或移除 EXIF 中的用户输入字段
  - 文件：照片处理服务
  
  **3. 文件重命名策略**
  - 上传文件使用 UUID 重命名，避免路径遍历
  - 存储路径不依赖用户输入
  - 文件：对象存储服务

- [ ] **分享 Token 安全**
  
  **1. Token 生成算法加固**
  - 使用 `SecureRandom` 生成 Token
  - Token 长度至少 32 字节（Base64 编码后 43 字符）
  - 避免可预测的时间戳或递增 ID
  - 文件：`ShareLinkService.java`
  
  **2. Token 使用频率限制**
  - 单个 Token 在短时间内的访问次数限制（防止暴力枚举）
  - 使用 Redis 计数器（滑动窗口）
  - 超过阈值后临时封禁 Token
  - 文件：限流中间件
  
  **3. 异常访问模式告警**
  - 检测短时间内大量不同 Token 的访问（扫描行为）
  - 检测来自同一 IP 的大量失败访问
  - 记录异常访问日志并告警
  - 文件：安全监控服务

- [ ] **XSS/CSRF 防护审计**
  
  **1. 用户输入的 HTML 转义**
  - 照片标题、相册描述的 XSS 防护
  - 前端使用 `v-text` 而非 `v-html`
  - 后端使用 OWASP Java Encoder
  - 文件：前端组件、后端响应处理
  
  **2. Viewer postMessage 通信加固**
  - 严格校验 `event.origin`（当前已有部分实现）
  - 校验 `event.source` 窗口来源
  - 校验消息 Schema（使用 Zod 或 JSON Schema）
  - 拒绝未知消息类型
  - 文件：`apps/gallery-viewer/src/App.vue`
  
  **3. CSP 配置**
  - Content Security Policy 响应头
  - 限制脚本来源、样式来源、图片来源
  - 禁止内联脚本（或使用 nonce）
  - 文件：`nginx.conf`、API 响应头配置

**交付标准**：
- ✅ 无敏感信息泄露到日志或响应
- ✅ 上传文件无法绕过类型检测
- ✅ Token 无法被暴力枚举
- ✅ 通过 OWASP ZAP 或类似工具扫描，无高危漏洞
